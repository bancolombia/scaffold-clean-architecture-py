# Security Policy

## Reporting a vulnerability

If you discover a security vulnerability in **scaffold-ca-python**, please report it responsibly by email:

- **Email:** [oficina_open_source@bancolombia.com.co](mailto:oficina_open_source@bancolombia.com.co)

Please **do not report security vulnerabilities through public GitHub issues, discussions or pull requests**, and do not disclose them publicly until the maintainers have reviewed and addressed them.

Include as much of the following as you can:

- The affected version (`pip show scaffold-ca-python`) and Python version.
- The command or code path involved, and whether the issue is in the CLI itself or in the code it generates.
- Steps to reproduce, or a proof of concept.
- The impact you expect (for example: code execution, path traversal, secret exposure, vulnerable dependency).

## Scope

This policy covers:

- **The CLI** — the `scaffold-ca-python` package published on PyPI and the code in this repository.
- **Generated code** — files produced by the templates, including the dependency versions they pin. A template that generates insecure code or pins a vulnerable dependency is in scope.

Vulnerabilities in third-party libraries should also be reported to their own maintainers; let us know if a generated project is affected so the pinned version can be updated.

## Supported versions

Releases are cut from `main` and there are no maintenance branches, so security fixes ship in a new release of the latest minor version.

| Version | Supported |
|---|---|
| 1.2.x | ✅ |
| < 1.2 | ❌ |

Upgrade to the latest release to receive fixes. For projects generated by older versions, run `scaffold up` to apply upgrade actions and refresh dependencies.
