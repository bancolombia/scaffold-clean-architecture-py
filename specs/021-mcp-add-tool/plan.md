# Implementation Plan: Incremental MCP Tool Addition

**Branch**: `feature/021-mcp-add-tool` | **Date**: 2026-10-15 | **Spec**: [spec.md](./spec.md)

**Input**: Feature specification from `/specs/021-mcp-add-tool/spec.md`

## Summary

Add a new `--add-tool` flag to the existing `scaffold gep` / `generate-entry-point` command, usable only with `--type mcp`. When invoked against a project that already has an MCP entry point, it validates `--name`, repeatable `--param name:type`, `--returns`, and `--description`, then appends exactly one new `@mcp.tool(...)`-decorated async stub function **inline inside `bind_tools`** (appended to end of file with 4-space indentation, since `bind_tools` is always the last function) to `tools.py` (and a matching registration assertion to `test_tools.py`) using a new `ModuleBuilder.append_to_file` primitive (append-or-create; no textual anchor/marker) and a dedicated Jinja2 template. No domain model, use case, gateway, or driven adapter is generated. The command fails with actionable, non-crashing errors for every invalid input, for missing entry points, for duplicate tool names, and for projects generated by a pre-feature scaffold version that lack the required `bind_tools` async function pattern.

## Technical Context

**Language/Version**: Python 3.13+ (matches `requires-python = ">=3.13"` in `pyproject.toml`; no change)

**Primary Dependencies**: Typer (CLI), Rich (console output), Jinja2 (template rendering), Pydantic v2 (context/validation models) — all already in `[project.dependencies]`. The Python standard-library `ast` module (already used by `core/structure_validator.py`) is reused for type-expression grammar validation and for detecting already-registered tool names in `tools.py`. **No new runtime dependency is introduced.**

**Storage**: N/A — operates on local filesystem files within the target generated project (`tools.py`, `test_tools.py`)

**Testing**: pytest + pytest-cov, following the existing `tests/commands/`, `tests/factory/entry_points/`, and `tests/templates/` conventions; 80% line-coverage gate per Constitution Principle V

**Target Platform**: Cross-platform CLI (Linux/macOS/Windows), distributed as the `scaffold-ca-python` PyPI package — no change from existing `gep` command

**Project Type**: Single project — CLI tool extension (new flag + guard logic on an existing command, two new small Jinja2 templates, structural rewrite of `tools.py.jinja2`/`test_tools.py.jinja2` to a registrar-list pattern instead of anchor comments)

**Performance Goals**: N/A — single-shot, sub-second CLI invocation; same expectation as all other `generate-*` commands, no new performance envelope

**Constraints**:
- MUST NOT change the existing (no-flag) `scaffold gep --type mcp` creation behavior — `--add-tool` is strictly additive.
- MUST route all generated code (the tool stub, the test addition) through Jinja2 templates under `src/scaffold_ca_python/templates/` per Constitution Principle II — no f-string/string-concatenation code generation.
- MUST NOT use a textual/comment marker ("anchor") as the insertion mechanism for `tools.py`/`test_tools.py` — a comment telling the developer "do not remove" is not acceptable in generated code. Instead, MUST add a new `ModuleBuilder.append_to_file` / `FileWriter._apply_append_to_file` primitive (append-or-create semantics: appends to the end of an existing file, or creates the file if it does not exist). `tools.py.jinja2` MUST NOT be restructured — its existing simple `@inject async def bind_tools(...)` pattern is the insertion target; new tool stubs are appended to the end of the generated file (effectively inside `bind_tools`) with 4-space indentation, using `AppendToFile`.
- MUST NOT modify or remove the existing `ModuleBuilder.insert_after` / `FileWriter._apply_insert_after` / `InsertAfter` primitive — it remains used elsewhere (e.g. `EntryPointMcp.build()`'s `HOST`/`PORT` injection into `config.py`, anchored on the real `LOG_LEVEL` field) and is out of scope for this feature.
- MUST NOT introduce new third-party dependencies.

**Scale/Scope**: One CLI command module extended (`commands/generate_entry_point.py`), one new focused core module for validation/parsing, two new Jinja2 templates, a structural rewrite (registrar-list pattern) of two existing Jinja2 templates, a new `AppendToFile` file-operation primitive (additive, alongside the untouched `InsertAfter`), corresponding test additions across `tests/commands/`, `tests/templates/`, `tests/core/`, and `tests/factory/`.
